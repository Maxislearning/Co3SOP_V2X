# 留一个 run 交叉验证（任务35）

生成日期：2026-10-24。脚本：`tools/loro_cv.py`（划分）、`tools/loro_lane.sh`（训练和导出）、`analyze_loro.py`（本目录）。

## 设置

- 6 折，每折把一个 source run 当测试集。legacy 那一折只测 sid 627–783（314 行），因为 Stage2B 用 sid 2–626 训练过；其余 5 折测试整个 run（1108–1291 行）。
- 早停用的内部验证集：每个训练 run 的最后 15% sample_id，前面空出 10 个 sample_id 不用。测试 run 不参与任何选择。
- 模型：A2（分层结构 + 面板 sqrt 反频率加权），**`--coord-conv gated`**：拼上坐标通道，并乘以占用率。
  - 不加坐标通道时，gt/target 会欠拟合，见任务35 的诊断。
  - dense 写法（坐标铺满整个网格）开局会在多数类上停 3–8 个 epoch，和早停冲突；那一轮已作废，结果在 `../cc_dense_aborted/`。
- 1 个训练种子（`--seed 0`），4 个组合，共 24 次训练。Stage2B 冻结，没有重训。
- 分析单位是测试 run（n=6）；组合之间按 run 配对；主指标是面板对准确率（TX、RX 两侧面板都选对）。

## 结论

1. **GT 下加 scene 没有用，而且这一点估计得很准**：区间是 [−2.2, +1.1] 个点，在 10 个点的最小关心差异以内，可以写成“没有实际意义的差异”。任务34b 的 +15.9 点确认是模型结构造成的假象。
2. **预测 occupancy 比 GT 损失 14–18 个点**，6 个 run 里有 5–6 个方向一致。在 t 检验假设下，Holm 校正后 p < .05；置换检验在 n=6 时做校正后达不到 .05。损失主要集中在左右面板（34–45 个点），也就是超车、并排这类场景。
3. **预测下加 scene**：平均 +3.0 点，区间很宽，几乎全部来自 seed1 一个 run（+21.8 点）。左右面板上有偏正的趋势（+11.5 点，4/6 个 run 为正），但不确定。任务34b 的“偏向变差”在新设置下不成立。
4. **NLOS 完全没有被学到**：所有模型对 NLOS 行都只输出前后面板（目标所在方向），而 NLOS 的最佳面板分布在四个面板上。4 个组合的准确率完全相同（.385/.049/.244）。测试集里只有 legacy、seed2、seed5 有 NLOS（共 108 行，6 个事件），训练集里更少。
5. **legacy 的左右面板（48 行）所有模型都是 0**，原划分下也是这样。

## 限制

- 只有 1 个训练种子。原结构下单个 run 内的种子噪声是 3–7 个点，所以 seed1 上的 +21.8 可能有一部分来自训练随机性。
- n=6；置换检验做 Holm 校正后最小只能到 0.125。
- 内部验证集也是训练 run 的时间尾段。不过测试 run 是独立的，选择偏差只影响 epoch 的选择，不会污染测试结果。
- legacy 折的测试集小（314 行），而且训练用的 legacy 帧对 Stage2B 来说是“见过”的。按方案要做的敏感性检查（`loro_cv.py --drop-stage2b-train`）还没有跑。
